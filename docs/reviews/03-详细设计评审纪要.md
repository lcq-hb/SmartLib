**本次会议的红线（会前由 Tech Lead 宣读）**

1. **库存扣减零容忍**：任何扣减路径（Service、Agent 工具、补偿任务、脚本）都必须带 `available_copies >= #{n}` 条件；无约束 update 视为**致命缺陷**，直接不通过。
2. **无实测不写数**：详细设计不得出现编造的实测性能数值，容量与内存均为"测算/待实测回填"。
3. **失败路径必须可观测**：任何降级、补偿、对账失败都必须有日志 + 指标 + 告警，不允许静默失败。

### 2.3 关键设计决策清单（本会确认）

| 决策项 | 设计稿方案 | 是否需 ADR |
|---|---|---|
| 库存扣减唯一入口 | `BookStockMapper.deduct(bookId, n)` 强制带条件；Service 层禁止直接 `update` | ADR-003（已在 Gate-2 立项，本会补强制手段） |
| 事务边界 | "校验 + 扣减 + 写流水 + 写借阅记录"在**同一本地事务**内 | 否 |
| 锁顺序 | 统一"先 `book_stock` 行，后 `borrow_record` 插入"；禁止跨表乱序加锁 | 否 |
| 幂等实现 | `IdempotencyAspect` + `idempotent_record` 表，唯一键冲突即返回缓存结果 | ADR-006 |
| 缓存一致性 | Cache-Aside + 延迟双删 + 版本号校验；库存不缓存 | ADR-008 |
| 预约队列 | `queue_no` 单调递增 + DB 行锁取号；FIFO 由 `(book_id,status,queue_no)` 索引保证 | 否 |
| Agent 事实性约束 | 无工具证据不下结论；数字必须来自工具返回 | ADR-007 |
