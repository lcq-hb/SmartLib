## 1. 速查表：症状 → 诊断

| 症状 | 最可能的原因 | 详见 |
|---|---|---|
| `No module named 'pydantic_settings'` | 忘了设 `PYTHONPATH=.tools/pylibs` | §2.2 |
| `pip install` 报错 / venv 里没有 pip | 本机 Python 的 `ensurepip` 是坏的 | §2.1 |
| 终端里中文显示成 `������` | PS 5.1 控制台是 GBK，数据没错 | §2.3 |
| `mvn` 报找不到依赖，明明传了 `-Dmaven.repo.local` | `mvn.cmd` 把中文路径参数弄丢了 | §2.4 |
| `mvn.ps1` 报"缺少 }"或乱码语法错 | 脚本丢了 UTF-8 BOM | §2.4 |
| `Invoke-WebRequest` 报 `SEC_E_NO_CREDENTIALS` | Windows schannel 问题，换 Python/Node 发请求 | §2.6 |
| Agent 起来了但所有工具 `UPSTREAM_ERROR` | 后端没起 / 起在别的端口 / 变量名写错 | §3.4、§5.1 |
| 新进程 `exit code 1`，但旧服务还能访问 | 端口被旧进程占着，新进程 bind 失败 | §3.5 |
| `git show --name-only` 的中文路径 checkout 不上 | git 给非 ASCII 路径加了引号转义 | §3.1 |
| PS 重定向生成的文件 Python 说 `Non-UTF-8 code starting with '\xff'` | PS 的 `>` 写出 UTF-16LE | §3.2 |
| PS 里 `git commit -m "...${VAR}..."` 报解析错 | 双引号内 `${}` 被 PowerShell 当变量 | §3.3 |
| 改了静态资源但浏览器还是旧页面 | 应用启动时把资源拷进 `target/classes`，改动在启动之后 | §3.6 |
| 应用启动直接失败 `'initialDelay' not supported for cron triggers` | `@Scheduled` 同时给了 cron 和 initialDelay | §4.5 |
| 还书接口 `BindingException`，返回 null | UPDATE 语句被标成了 `@Select` | §4.4 |
| 启动时 `NullPointerException` 在 `Map.copyOf` | 往里塞了 null 值 | §4.6 |
| 检索 SQL 报 `There is no getter for property named 'offset'` | 只写了 `offset()`，MyBatis 要 `getOffset()` | §4.7 |
| 浏览器里调 Agent 报 CORS 错 / OPTIONS 405 | 没挂 CORS 中间件；或端口上是旧进程 | §4.8、§3.5 |
| 配置改了没生效，行为"回到默认值" | 变量名或取值写错，被静默忽略 | §5.1 |
| 单测全绿但功能是坏的 | 见 §5.2 的**五种典型形态** | §5.2 |
| 超时之后"报成功 N 次、实际扣了 N+2 次" | 超时 + 副作用 + `cancel(false)` 无效 | §5.3 |
| 某个依赖挂掉后，延迟反而涨 20 倍 | 降级路径没有短路，每请求付一次连接超时 | §5.4 |
| 200 并发下大量超时，但低并发一切正常 | 事务里等别的线程，连接池被占死 | §5.5 |
| 程序逻辑没错，但整份报告打不出来、退出码非零 | 输出里有当前编码表示不了的字符 | §5.6 |

## 2. 本机环境特有（🖥️ 换机器即作废）

> 这一节只描述**当前这台 Windows 开发机**的实际情况。换机器后大概率全部消失，
> 但"遇到这类环境问题怎么绕过去"的**思路**是可迁移的。

### 2.1 Python 装不了包：`ensurepip` 坏 + 沙箱限制

**现象**
- `python -m venv .venv` 之后 `.venv\Scripts\pip.exe` 不存在
- `pip install` 失败，`ensurepip` 报 `PermissionError`
- 原因有两层：① 这台机的联想商店版 Python 的 `ensurepip` 本身有问题；
  ② 沙箱不允许往 TEMP 的子目录写东西，而 `ensurepip` 要在那儿解压

**绕法（当时用的）**
```powershell
python -m venv --without-pip --system-site-packages agent-service\.venv
# 运行期依赖装到基础环境，测试依赖单独下到 .tools/pylibs
```
**代价**：依赖被拆成两处，所以必须设 `PYTHONPATH`（见 2.2）。

**经验**：环境坏了就去修环境，别在坏环境上叠一层又一层绕法。
这次为了不耽误交付才绕，代价是后面每个命令都要多一行 `PYTHONPATH`。
换台机器用官方安装包，`python -m venv` + `pip install -r requirements.txt` 一次就过。

### 2.2 `PYTHONPATH` 是必需的，不是可选的

`pytest`、`pydantic_settings` 装在 `<仓库根>\.tools\pylibs`，不在 venv 的 site-packages 里：

```powershell
$env:PYTHONPATH="C:\Users\<user>\Desktop\简历项目\.tools\pylibs"
```

忘了它就报 `No module named 'pydantic_settings'`（连 `uvicorn` 都起不来）。

### 2.3 PowerShell 控制台是 GBK：中文一定乱码

**现象**：任何打印中文的命令，输出都是 `������`。**数据是对的，只是显示问题。**

**判断口诀**：如果乱码只在终端出现、写进文件用编辑器打开正常，那就是编码显示问题，不要去改程序。

**处理**
- 看中文一律用浏览器（演示控制台）或写文件后打开
- 必须看终端时：`... | Out-File -Encoding UTF8 x.txt` 再用编辑器看
- 绝对不要为了"让终端显示正常"去把中文换成英文 —— 那是本末倒置

### 2.4 Maven 必须走 `scripts/mvn.ps1`

两个独立问题叠在一起：

1. **`mvn.cmd` 会丢参数**：它是批处理，`cmd.exe` 用系统代码页解析命令行，
   `-Dmaven.repo.local=C:\...\简历项目\.tools\m2repo` 这种带中文的参数会被弄坏，
   表现为"依赖下载到了别处"或"找不到依赖"。
   绕法：直接用 `java -classpath plexus-classworlds-*.jar org.codehaus.plexus.classworlds.launcher.Launcher`（`mvn.ps1` 干的就是这件事）。
2. **`mvn.ps1` 必须带 UTF-8 BOM**。PowerShell 5.1 读**没有 BOM** 的文件会按 ANSI(GBK) 解释，
   脚本里的中文注释直接变成乱码 → 解析报"缺少 }"。

**经验**：Windows 上的 `.ps1` 只要有非 ASCII 字符，就存成 **UTF-8 with BOM**。
写脚本时用 `utf-8-sig`（Python）或 `Out-File -Encoding utf8BOM`。

### 2.5 PowerShell 5.1 的语法限制

本机是 Windows PowerShell 5.1（不是 pwsh 7），不支持：

| 写法 | 5.1 结果 |
|---|---|
| `$a ?? $b` | 解析错误 |
| `$a?.b` | 解析错误 |
| `$cond ? $x : $y` | 解析错误 |

**经验**：脚本要么显式兼容 5.1，要么在开头判断版本并提示。别假设用户有 pwsh 7。

### 2.6 HTTPS 走不通：schannel 凭据问题

`Invoke-WebRequest`、`curl.exe` 访问 https 报 `SEC_E_NO_CREDENTIALS`。
同一台机器上用 **Python** 或 **Node** 发 https 请求正常。

**处理**：需要联网核实时改用
```powershell
python -c "import urllib.request as u; print(len(u.urlopen('https://...', timeout=30).read()))"
```

### 2.7 沙箱的两个附带影响

- **不能往 TEMP 的子目录写**：`ensurepip`、某些工具的解压步骤会失败
- **`pytest-cache-files-*` / `.pytest-tmp` 删除不掉**（ACL 拒绝）

**处理**：这类目录已经写进 `.gitignore`，让它们躺在那里即可，不要反复尝试删除浪费时间。

## 3. 工具与命令的坑（🔁 可迁移）

### 3.1 git 会给非 ASCII 路径加引号转义

```powershell
# 错误认知：拿到的是真实路径
git show --name-only <commit>
# 实际输出： "docs/03-\350\257\246\347\273\206\350\256\276\350\256\241.md"
```

用这个路径去 `git checkout <commit> -- <path>` 会 `pathspec did not match`，
而且**只要有一个路径失配，整条 checkout 命令全部中止**（其他文件也不会被恢复）——
很容易误判成"已经恢复了"。

**正确做法**：用 `-z`（NUL 分隔，git 不做任何转义）
```python
raw = subprocess.run(["git","show","--pretty=format:","--name-only","-z",commit],
                     capture_output=True).stdout
names = [n.decode("utf-8") for n in raw.split(b"\x00") if n.strip()]
```

### 3.2 PowerShell 的 `>` 写出的是 UTF-16

```powershell
git show <commit>:path/to/file.py > out.py    # out.py 是 UTF-16LE 带 BOM
python out.py                                  # SyntaxError: Non-UTF-8 code starting with '\xff'
```

**正确做法**：让源程序自己写文件
```python
blob = subprocess.run(["git","show","<commit>:path"], capture_output=True).stdout
open("out.py","wb").write(blob)     # 二进制原样落盘
```

### 3.3 PowerShell 双引号里的 `${}` 会被当变量解析

```powershell
git commit -m "修 application*.yml 的 \${VAR} 占位符"   # 解析错误：变量引用无效
```
`${...}` 是 PowerShell 的变量语法，即使本意是字面量。

**正确做法**：提交信息写进文件，用 `git commit -F msg.txt`。
顺带解决了多行提交信息和引号嵌套的问题，**推荐所有多行 commit 都这么写**。

### 3.4 判断服务是否在跑：用 HTTP 探活，别信端口命令

`Get-NetTCPConnection -LocalPort 8080 -State Listen` 在服务**确实在跑**时返回过空
（可能是权限或时序问题），导致我误判"服务已停"，白重启了一次。

**可靠做法**
```powershell
try { (Invoke-RestMethod http://127.0.0.1:8080/actuator/health -TimeoutSec 3).status } catch { "down" }
```
或用 Python 的 `urllib` 拿到**真实状态码**。探活要探"业务能应答"，不是"端口有监听"。

### 3.5 端口被旧进程占着：新进程静默失败

**现象**：新起的 Agent `exit code 1`，但 `/health` 仍然 200 —— 因为**旧进程还在服务**。
最坑的是旧进程跑的是**修改前的代码**，于是你会以为"我的修复没生效"。

这次就撞了：改完 CORS 后测预检仍然 405，实际打到的是改代码之前启动的进程。

**经验**
- 启动失败先看日志里有没有 `address already in use`
- 验证新代码前，先确认端口上是新进程（看启动日志的时间戳/配置行）
- 复用长驻服务做验证前，先重启它

### 3.6 改了静态资源，但浏览器还是旧页面

`mvn spring-boot:run` 在**启动时**把 `src/main/resources` 拷进 `target/classes`。
启动之后你改的 `static/*.html` 不会自动同步。

这次实测：磁盘上 31817 字节，服务端给的是 30419 字节（旧版）。

**处理**：改完静态资源要重启后端；判断方法是比对字节数或找一个新加的标记字符串。

## 4. 框架与库的坑（🔁）

### 4.1 Spring Boot 4 把 Jackson 从 `starter-web` 里拆出去了
加了 `spring-boot-starter-web` 仍然没有 Jackson → 序列化直接失败。
**修**：显式加 `spring-boot-starter-json`。
**经验**：大版本升级时，"我以为它包含"的东西要逐个验证，别凭旧印象。

### 4.2 Spring Boot 4 移除了 `TestRestTemplate`
**修**：测试改用 JDK 自带的 `java.net.http.HttpClient` + 字符串断言。
**顺带的好处**：少一层框架依赖，测试更容易看懂。

### 4.3 Jackson 3 的包名变了
`com.fasterxml.jackson.*` → `tools.jackson.*`。IDE 自动导入很容易导错版本。

### 4.4 `@Select` 用在 UPDATE 上 → `BindingException`
```java
@Select("UPDATE borrow_record SET status='RETURNED' WHERE id=#{id}")
int markReturned(long id);        // 运行时 BindingException，且返回 null 拆箱失败
```
`@Select` 只用于查询。**症状是"还书功能 100% 失败"**，但编译期完全正常。
**经验**：注解型 MyBatis 的 SQL 类型必须与注解匹配，这类错误只有运行到才暴露。

### 4.5 `@Scheduled` 不能同时给 cron 和 initialDelay
```java
@Scheduled(cron = "0 0 2 * * ?", initialDelay = 60_000)   // 启动即失败
// IllegalStateException: 'initialDelay' not supported for cron triggers
```
**更值得记住的是它为什么没被测试发现**：测试 profile 把定时任务的 Bean 关掉了，
所以测试全绿、应用起不来。**这就是"必须真实启动一次"的最有力论据。**
**修**：去掉 `initialDelay`；补一个 `ScheduledTasksWiringTest` 专门守住装配。

### 4.6 `Map.copyOf` 不接受 null 值
```java
map.putIfAbsent(key, null);   // 允许
Map.copyOf(map);              // NPE
```
**经验**：不可变集合的工厂方法大多是"不接受 null"的。构造配置快照时要么过滤 null，要么显式处理"键存在但无值"的语义。

### 4.7 MyBatis 的 `#{obj.field}` 只认标准 getter
```java
public int offset() { ... }        // 不认
public int getOffset() { ... }     // 认
```
`#{q.offset}` 报 `There is no getter for property named 'offset'`。
**修**：加标准 getter，同时保留 `offset()` 作为便捷别名。

### 4.8 FastAPI 中间件顺序：后加的在外层
`app.add_middleware()` 是**插到最前面**（最外层）。所以 CORS 能先于业务中间件处理 OPTIONS 预检。
**没有 CORS 中间件时，`OPTIONS` 会返回 405**（不是你配置错，是压根没配）。
**另一个实测点**：来源不在白名单时，Starlette 的预检返回 **400**（而不是静默通过）。

### 4.9 `pydantic-settings` 对 `list` 类型按 JSON 解析
```python
cors_origins: list[str] = [...]     # CORS_ORIGINS=http://a,http://b 会校验失败
```
**修**：用 `str` + 逗号分隔，需要时再 split（对照见 `agent-service/app/config.py`）。

### 4.10 Python 3.12 + uvicorn 需要 `pydantic_settings` 可导入
框架把它当运行期依赖，但没装就会在 import 阶段炸，报错信息不会告诉你是"环境少包"。

## 5. 六类 bug 模式（🧠 最值钱的部分）

> 单个 bug 修完就忘了，模式才会复用。下面四类是这个项目里反复出现的形态。

### 5.1 静默失效：写了，但不生效

**共同特征**：不报错、不告警，行为只是"回到默认值"。本地永远测不出来。

**这个项目里的 5 个实例**

| 实例 | 为什么本地看不出来 |
|---|---|
| 环境变量名写错（`SMARTLIB_BACKEND_BASE_URL` vs `JAVA_BASE_URL`） | 默认值恰好也是 `127.0.0.1:8080` |
| 给 Agent 传 `SMARTLIB_INTERNAL_SIGN`，而它读 `INTERNAL_SIGN_SECRET` | 两边默认密钥相同，掩盖了问题 |
| k8s Secret 写 `OPENAI_API_KEY`，而 Agent 读 `LLM_API_KEY` | 默认走 mock，看不出 Key 没生效 |
| 后端占位符叫 `${STOCK_STRATEGY}`，部署键叫 `SMARTLIB_STOCK_STRATEGY` | 占位符默认值恰好等于想设的值 |
| 策略值写 `optimistic_db`，而 `name()` 返回 `optimistic-db` | 工厂找不到就回落默认策略，日志只有一行 WARN |

**共同点**：**"兜底默认值"和"我以为设的值"恰好相等**，所以静默失败被完美掩盖。

**怎么防**
1. **名字即契约**：配置项的名字必须有唯一权威来源（这里是 `config.py` 的字段名 + `application*.yml` 的占位符），
   部署侧只能引用，不能自创。
2. **加机器守卫**：写脚本从代码侧提取权威名单，交叉校验部署/CI/脚本里出现的每一个名字
   （修 §5.1 那批问题时用过这个办法，一次性列出 9 个可疑名字、其中 6 处是真问题；
   脚本未纳入仓库，见 §6）。
3. **取值也要校验**：枚举值拼错和名字拼错是同一类问题，同样应该机器校验。
4. **启动时打印生效值**：`/health` 里回显 `java_base_url`、`cors_origin_list`，一眼能看出实际生效的是什么。

### 5.2 测试全绿，但功能是坏的

这是最危险的一类：**测试给了你虚假的安全感**。这个项目里出现了五种形态：

| 形态 | 实例 | 为什么测试没抓到 | 靠什么抓到的 |
|---|---|---|---|
| **两侧约定不对称** | 索引侧存 `py:jsjwl`，查询侧只生成裸词项 `jsjwl` | 两侧各有单测，都"自洽" | 端到端检索用例 |
| **被测对象在测试环境里被关掉** | `@Scheduled` 配置非法，但测试 profile 禁用了定时任务 | Bean 根本没创建 | 真实启动一次 |
| **测试夹具与真实数据不一致** | 两侧种子 SQL 各写一份（24 vs 14 本书） | 测试用自己的 H2 | 对比两侧文件 + CI 守卫 |
| **缓存让新值读不到** | 借出后详情接口仍显示旧库存，因为没人失效缓存 | 单测直接查库，绕过缓存 | 真实压测 |
| **字符集** | `✅/❌` 让评测报告打印崩溃、退出码非零 | 只在特定控制台编码下崩 | 换环境跑一次 |

**经验（可以直接背下来）**
> **单元测试只能证明"每个零件自洽"，不能证明"零件之间接得上"。**
> 所以除了单测，必须有三样东西：
> ① **真实启动一次**（装配错误只有启动才暴露）；
> ② **跨进程/跨语言端到端跑一遍**（约定不对称只有联调才暴露）；
> ③ **两侧文件的一致性守卫**（复制粘贴出来的两份数据早晚会漂）。

### 5.3 超时 + 副作用 = 数据不一致

```java
Future<Boolean> f = pool.submit(task);
try { return f.get(200, MILLISECONDS); }
catch (TimeoutException e) {
    f.cancel(false);       // 任务已经开始执行，取消失效！
    return fail();         // 但扣减已经发生了
}
```
**症状**：并发压测"报成功 8 次，实际扣减 10 次"。

**根因**：`cancel(false)` 只能取消**还没开始**的任务。已经开始的任务会继续跑完，
于是"调用方认为失败、实际已生效"。

**修**：区分两种情况
- `cancel(false)==true` → 确实没执行，可以安全返回失败
- `cancel(false)==false` → 已经/正在执行，**必须等结果**再决定返回什么

**更根本的经验**
> 任何"超时"都必须先回答一个问题：**超时之后，那个操作到底发生了没有？**
> 如果不能确定，就不要让它有副作用 —— 或者让它**幂等**，靠重试收敛。

对应到写操作的三件套：**幂等键**（重试不重复生效）、**可对账**（事后能发现偏差）、**唯一入口**（不给人绕过去的机会）。

### 5.4 降级路径本身成为故障

Redis 不可用时，`redis-lua` 策略按设计降级到数据库更新 —— 但每个请求都要付一次连接超时，
实测 **P99 从 27ms 恶化到 621ms**。加了短路（失败 3 次后 10 秒内直接走降级，不再尝试连 Redis）
之后回到 **351ms**。

**经验**
> **降级不是"多写一个 catch"，而是要像对待主路径一样对待它**：
> ① 降级判断本身要够快（有短路/熔断）；
> ② 降级要有可观测（降级计数、日志）；
> ③ 降级要能被测试（本机没有 Redis，正好天然覆盖了这条路径）。

顺带一个反向经验：**健康检查不该被可降级依赖拖死**。
Redis 健康指示器让 `/actuator/health` 变成非 UP，会导致编排系统把健康实例摘掉 ——
对一个"Redis 挂了也能工作"的系统来说这是错的。已显式关闭该指示器。

### 5.5 并发下的资源耦合

`mq-serial` 策略最初在**调用方事务里**等待工作线程结果：调用方占着一条数据库连接，
工作线程拿不到连接 → 200 并发下连接池死锁。

**修**：策略声明 `writesOwnLedger()`，此类策略不走调用方事务。
**残留边界要诚实写清**：上游若已有事务，风险仍在；生产应改为"返回 202 + 异步回调"。

**经验**
> **"在事务里等另一个线程"是并发事故的高发形态。**
> 事务占的不只是数据行，还有连接；等待会把这个稀缺资源锁死。

### 5.6 一个装饰性字符，能让整份输出消失

评测脚本把 `✅/❌` 放进报告，在 GBK 控制台上 `print(markdown)` 直接抛 `UnicodeEncodeError`：
**整份报告一个字都打不出来，退出码还是非零**，看起来像"评测失败"——
实际所有用例都通过了。

**修（两道）**
1. 报告里的装饰符号改成目标编码能表示的写法；
2. 输出加兜底：按当前控制台编码 `errors="replace"`，以后新增任何字符都不会让报告崩掉。

**经验**
> 日志/报告的输出路径，必须假设"目标终端是未知编码"。
> 尤其在中文 Windows 上：**GBK 编不出 emoji、✅、部分箭头**。

## 6. 把教训变成守卫（而不是变成注释）

**当前仓库里有 2 个守卫**，都跑在 CI 的 `guards` job 里（秒级）：

| 守卫 | 守住什么 | 对应上面哪个坑 |
|---|---|---|
| `scripts/tools/check_sql_sync.py` | 后端与部署两侧的 schema/种子数据必须一致 | §5.2 第三形态 |
| `scripts/tools/gen_entities.py --check` | 生成的实体/DTO 与生成器一致（有人手改就报错） | 手改生成代码 |

**还有第 3 个（环境变量名守卫），修 §5.1 那批 bug 时写过并验证有效，但目前没有纳入仓库**
（拟放入未入库的 `scripts/tools/check_env_names.py` + CI 里一行调用，约 235 行）。
意味着：**§5.1 那一类"变量名写错但静默失效"的问题，现在仍然会复发**。
如果要把这个守卫加回来，照下面的三条经验写即可。

**写守卫的三条经验**

1. **守卫要快**。秒级才能进 CI 门禁；要跑几分钟的守卫最后都会被绕过。
2. **守卫必须有唯一权威来源**。比如环境变量名以 `config.py` 字段名 + `application*.yml` 占位符为准，
   而不是维护一份"正确名字清单"（那只是把同一个问题换个地方犯）。
3. **误报会杀死守卫**。第一版守卫把 Python 模块常量 `STOCK_CSV_COLUMNS` 当成环境变量报了，
   还把 Spring 宽松绑定认识的 `SMARTLIB_ADMIN_ENABLED` 误判了。
   误报多了就没人看输出 —— 所以要么精确识别，要么明确写进豁免名单**并注明理由**。

**断言不变式，而不是断言数值**

对账用例没有去断言"库存应该等于 3"，而是断言：
```
成功数 ≤ 10  ∧  库存 = 10 - 成功数  ∧  sum(账本) = -10  ∧  库存 ≥ 0
```
这样即使实现改了、性能变了，只要**守恒**被破坏就会红。
**数值会变，不变式不会。**

## 8. 如果重做一遍（🧠 设计层面的经验）

1. **先定"唯一入口"，再写实现。** 库存扣减只能有一个入口方法，所有策略都藏在它后面。
   一旦有第二条路径能改库存，"不超卖"就不再是系统性质，而是"大家自觉"。
2. **配置项的名字就是契约。** 名字定下来就写守卫，别指望人记。
   尤其**取值也是契约**（枚举值拼错和名字拼错一样致命）。
3. **易变字段不要进长 TTL 缓存。** `availableCopies` 这种字段，
   TTL 应该按"可接受的偏旧时长"定，而不是按"数据变更频率"定。
   多实例下 L1 缓存无法被其他实例清除，短 TTL 是唯一诚实的兜底。
4. **外部依赖一律可降级，且降级必须有短路。** 否则"高可用设计"会变成"故障放大器"。
5. **写操作三件套**：幂等键、二次确认、可对账。缺一个就会出现"用户以为没成功、实际已生效"。
6. **Agent 的事实必须有工具证据。** 模型给的 ID/数字一律不可信；
   拿不到证据就说"没查到"，不要编 —— 这条比任何效果指标都重要。
7. **时区、编码、中文路径在第一天就定死**，别等到第 30 天才发现日志全是乱码。
8. **"跑一次"和"测一遍"是两件事。** 测试证明零件自洽，启动证明零件能装在一起。
   这个项目里两个最严重的启动期错误（`@Scheduled`、`Map.copyOf`）都是测试全绿、启动即炸。
